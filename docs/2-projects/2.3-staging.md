# 2.3 直接保存、审阅与恢复

RPG Agent MV 现在采用直接保存：在编辑器或 Agent 中确认保存后，地图、事件、数据库、插件和素材会直接写入当前游戏工程，不再进入另一套“暂存区”，也不再需要“应用全部”。

## 保存行为

- 单文件修改使用原子替换，避免把半份 JSON 留在工程里。
- 一次操作涉及多个文件时，要么全部写入成功，要么全部不写。
- 保存前会校验当前磁盘版本。文件若已被 RPG Maker 或其他程序改过，本次保存会被阻止，并要求重新读取；系统不会猜测如何合并。
- Inspector 中的撤销和重做只覆盖尚未保存的当前编辑过程。保存后如需恢复，应使用 Git 版本管理或自己的工程备份。

不要同时在 RPG Maker 和 RPG Agent MV 中编辑同一份数据文件。切回本产品后若发现外部改动提示，先重新载入工程事实，再决定是否重做本次编辑。

## 审阅改动

直接保存不等于跳过审阅。完成一次任务后，建议核对：

- Agent 在聊天流中的改动说明和阻断信息。
- 地图、事件、数据库和素材在编辑器里的实际结果。
- 当前工程的 Git 差异；需要里程碑时，在现有 **版本管理** 中保存一个本地版本。
- 涉及剧情、演出、插件或运行时行为时，执行对应试玩并人工确认。

现有 **版本管理** 管的是 Git 工程历史；**游戏版本** 管的是玩家看到的发行版本。两者彼此独立。

## 试玩与隔离验证

顶部 **Play** 启动当前源工程，所以已经保存的变化会立即进入试玩。游戏仍可能写入自己的 `save/` 目录。

Agent 自动验证会从已保存的源工程创建系统临时副本，并排除玩家存档。临时副本用于有限的结构和运行探针；验证结束后会检查源工程和存档没有被探针改动。通过机械检查不等于剧情、手感或画面已经由人验收。

## 发现错误时怎么恢复

1. 尚未保存：使用当前编辑器的撤销或重做。
2. 已保存且启用了 Git 版本管理：查看差异，保存当前现场后再从明确的历史版本恢复所需文件。
3. 已保存但未启用版本管理：从自己的工程备份恢复，或重新执行一次明确的反向修改。
4. 遇到外部修改冲突：不要反复点击保存；先重新载入并确认哪一方的内容应保留。
