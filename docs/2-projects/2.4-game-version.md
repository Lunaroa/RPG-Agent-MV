# 2.4 游戏版本与存档兼容

**游戏版本**是玩家可见的发行版本，独立于 Git 的 **版本管理**。它保存在游戏工程的 `RPGAgentRelease.json` 中，并由受管插件在游戏启动、保存和读取存档时使用。

该功能是模块市场中的内置模块，默认关闭。先在 **模块市场** 启用“游戏版本”，左侧才会出现对应入口。停用模块只隐藏产品入口，不删除工程中已有的版本配置或受管运行时插件。

## 版本格式

接受 `a.b.c` 或 `a.b.c-xxx`，例如 `1.0.0`、`1.2.3-beta.2`。三段数字必须存在；后缀可由英文字母、数字和点组成。保存时会去掉数字段与后缀分隔符之间的空格。

在线更新比较只比较前三段数字，并按任意精度十进制整数比较。后缀用于渠道或展示，不参与大小判断；不同渠道由渠道字段隔离。同一完整版本可以重复构建，每次构建和发布都有新的内部发行 ID，因此可用于修复同版本坏包。

启动检查可以选择在 Windows 游戏中后台下载兼容更新；下载完成后才显示公告并询问是否安装。普通升级只在数字版本更高时自动提示，同数字版本的重新安装或修复只能由玩家手动检查更新触发。

## 游戏代码接口

受管插件安装后，可在事件脚本或自己的插件中使用：

```js
const version = globalThis.RPGAgentVersion.getVersion();
const parts = globalThis.RPGAgentVersion.getParts();
const compared = globalThis.RPGAgentVersion.compare('1.2.0'); // -1、0 或 1
const compatible = globalThis.RPGAgentVersion.isAtLeast('1.1.0');
const saveOrigin = globalThis.RPGAgentVersion.getSaveOriginVersion();
const saveChannel = globalThis.RPGAgentVersion.getSaveOriginChannel();
```

`compare()` 返回当前游戏版本相对于参数版本的比较结果。

## MV 与 MZ 插件命令

MZ 可在插件命令列表中选择 `RPGAgentVersion` 的以下命令：

- `GetCurrentVersion`：把当前游戏版本写入变量。
- `GetSaveOriginVersion`：把当前存档的起始版本写入变量。
- `CompareVersion`：把 `-1 / 0 / 1` 写入结果变量。
- `IsAtLeast`：把判断结果写入开关。
- `CheckForUpdates`：打开手动更新检查。

MV 使用同名文本命令，例如：

```text
RPGAgentVersion GetCurrentVersion 1
RPGAgentVersion GetSaveOriginVersion 2
RPGAgentVersion CompareVersion 1.2.3 3
RPGAgentVersion IsAtLeast 1.2.3 4
RPGAgentVersion CheckForUpdates
```

## 存档中的版本

新存档会在完整存档内容和存档列表摘要中写入首次创建时的游戏版本与渠道。旧存档没有这些字段时按“旧存档”策略处理。旧存档在新版本中再次保存时仍保留最初来源，便于长期判断迁移起点。

可分别配置旧存档、较旧版本、相同版本、较新版本和不同渠道的行为：直接允许、提示后允许、阻止，或交给开发者回调。回调必须同步完成；返回 `false` 或抛出错误会阻止载入。

```js
const unregister = globalThis.RPGAgentVersion.registerSaveMigration((context) => {
  if (context.originVersion === '1.0.0' && context.currentVersion === '1.1.0') {
    context.contents.system ??= {};
    context.contents.system.releaseMigration = '1.1.0';
  }
  return true;
});

// 插件卸载或不再需要时：unregister();
```

回调运行在存档正式载入之前。迁移逻辑由游戏作者负责，提交前应使用真实旧存档副本验证；当前机制不会替作者猜测业务数据怎样转换。
