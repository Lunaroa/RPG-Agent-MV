# 2.5 配置打包与在线更新

**配置打包**可以在不打开 RPG Maker 的情况下，从当前已保存工程生成 Web、Windows 和 Android 产物。打包转换只发生在独立临时副本中，不会把压缩、混淆或加密结果写回源工程。

该功能是模块市场中的内置模块，默认关闭。先在 **模块市场** 启用“配置打包”，左侧才会出现对应入口。停用模块不会删除打包预设、密钥引用、构建报告或已经生成的产物。“游戏版本”和“配置打包”可独立启用。

## 打包预设

每个工程可保存多个预设。预设包含目标平台、架构、输出位置、完整包或增量包、内容处理方式、Android 参数和可选上传设置。构建前会检查工程结构、插件、版本、基线、密钥、运行时和 Android 工具链；调用构建后若被这些检查阻断，会留下带失败阶段和恢复原因的失败报告，不会冒充成功产物。

输出冲突时可以覆盖、生成带编号的新目录或取消。成功构建会记录文件清单、SHA-256、Git 提交（可读取时）、处理方式、产物摘要和内部发行 ID。

## 三类目标

- **Web**：生成可部署目录，可选额外 ZIP。浏览器中的游戏不能自行替换服务器文件，发布新站点内容即完成 Web 更新。
- **Windows**：从工程自带的完整 RPG Maker / NW.js 导出运行时生成可运行目录，可选 ZIP；若本机另有匹配引擎和架构的合规受管运行时，也可使用受管副本。当前产品不代为下载授权状态不明确的 NW.js 发行包；两者都不存在时会明确列出缺失条件并停止。内容更新由游戏外部更新器在游戏退出后应用，并保留回滚信息。
- **Android**：使用产品固定管理的 WebView 壳和 Gradle 工具链真实构建 APK。可同时输出 `arm64-v8a`、`armeabi-v7a` 和 `x86_64` 独立 APK，不通过复制改名伪造架构包。

## 压缩、混淆与加密

图片、音频、视频、数据库、脚本和自定义 UI 可分别选择处理方式。启用加密时使用工程本机私有目录中的 AES-256-GCM 密钥，并在构建副本中安装对应加载器。

客户端必须能解密自己的内容，所以运行时始终存在可恢复的密钥。这里的加密用于提高直接查看和批量复制的门槛，不等于 DRM，也不承诺无法逆向。无论是否加密，发布包仍强制记录 SHA-256。

## 发布目录和文件服务器

本地发布会生成顶层 `releases.json`，以及按 `games/<游戏>/<渠道>/<发行 ID>/` 组织的不可变产物。可以保留本地目录，或用 WebDAV / HTTP PUT 上传到自己的静态文件服务器；上传时先发送产物，最后更新索引。

一次发布可以填写多种语言的标题、更新说明和可选维护公告，并明确选择默认语言。玩家语言没有对应公告时会回退到默认语言；缺少默认语言内容或语言代码重复时会阻止发布。

服务器应允许游戏跨域读取索引和产物，并正确提供静态文件。建议使用 HTTPS。HTTP 可以工作，但传输、上传凭据和服务器身份不受 TLS 保护，界面会给出风险提示。

所有下载都校验字节数和 SHA-256。若启用 **更新清单签名**，产品创建 P-256 签名身份：私钥只保存在当前电脑的系统加密存储中，游戏只内置公钥。服务器上的游戏发行清单被改动、签名缺失或私钥不匹配时，玩家端会拒绝更新。未启用签名时，哈希只能发现损坏，不能独立证明内容来自开发者。

## 玩家端更新

启用 `RPGAgentUpdater` 后，可选择启动时检查，也可用插件命令手动检查。发布记录支持可选更新或强制更新，并显示本地化标题、说明和维护公告。

- Windows 先下载并校验内容，在游戏退出后由外部更新器替换文件；新版本启动自检失败时可恢复备份。
- Android 内容更新写入应用私有的版本目录，校验完成后原子切换；启动健康确认失败时回到上一份内容。
- Android APK 更新会再次核对应用 ID、整数版本和签名证书，然后交给系统安装器。玩家必须允许安装并确认系统安装界面。

文件增量包和二进制差分包必须指定一份精确的成功构建作为基线。客户端基线不匹配时不会硬套补丁，而会选择适用的完整包或报告当前没有可用包。

## 跨平台存档边界

首版保证同一平台内升级后继续读取原存档，但不把同一个物理存档文件直接交给 Web、Windows 和 Android 共用。Web 使用浏览器来源存储，Windows 使用本地游戏存档目录，Android WebView 使用应用私有存储；三者的路径、权限、生命周期和清理规则不同，直接共用会造成不可控的数据丢失或覆盖。

三端仍使用相同的游戏存档数据合同和版本字段，因此后续可以增加由玩家明确操作的导出/导入适配器，在导入前校验游戏、存档版本、渠道和数据摘要。该路线不需要账号或云存档，但需要用真实旧存档和各平台插件组合单独验收；它不阻断首版三平台打包。

## Android 首次准备

首次 Android 构建需要用户明确同意许可后安装固定工具链。当前固定组合为 Microsoft OpenJDK 17、Android SDK 命令行工具、Gradle 9.4.1、Android Gradle Plugin 9.2.1、Compile SDK 36、Build Tools 36.0.0 和 AndroidX WebKit 1.17.0。下载项和依赖缓存都会校验；准备完成后可离线构建。

调试包使用产品管理的调试身份。正式包需要导入已有签名文件，或在界面中创建 JKS 签名文件，并填写别名和密码。密码可选择通过系统加密存储记住。覆盖安装必须保持相同应用 ID、相同签名身份以及可接受的更高整数版本；重新生成密钥或更改应用 ID 代表新应用，不会继续升级旧安装。

Android 图标以预设中的工程相对路径为准。新建 Android 预设时，只在工程资源根的 `icon/` 目录恰好存在一张 PNG、JPEG 或 WebP 图片时自动选中；没有候选或有多个候选时必须明确选择，不按文件名或排序猜测。

## 验收边界

构建报告和自动测试只能证明产物结构、摘要和协议符合预期。正式交付前仍应在干净 Windows 环境、目标 Android ABI 真机以及实际文件服务器上各做一次安装、启动、存档、更新、断网和回滚验收。

Android 壳的技术取舍见 [Android WebView 打包架构决策](../android-webview-packaging-adr.md)。
